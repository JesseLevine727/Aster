# v1.3: Close the slow corner at 50 MHz

Status: **complete**.
Baseline: Aster v1.2 at `4955bfb`.

v1.3 pipelines the frozen design so its **slow-corner static timing closes at
50 MHz** (20 ns). The silicon already ran the full heterogeneous pipeline
correctly at 100 MHz at room temperature; this phase turns the 50 MHz operating
point into one the toolchain actually signs off, up from the 31.25 MHz baseline.

## Measured starting point

| Metric | Value |
| --- | --- |
| Functional ceiling (Pynq-Z1, room temperature) | 100 MHz, identical oracle checksum |
| Slow-corner closure at the 32 ns constraint | 34.9 MHz (WNS +3.384 ns) |
| Slow-corner closure at the 10 ns constraint | ~47.8 MHz (WNS −10.860 ns, 38 680 / 55 599 endpoints fail) |
| Worst path at 10 ns | 20.9 ns, NPU `rows` → engine `state` |

See [`docs/results/frequency/`](../results/frequency/README.md).

## Critical path clusters pipelined

| Cluster | Fix | Effect on the 20 ns constraint |
| --- | --- | --- |
| Perf-counter events → counters | register the event/increment inputs at each performance-block boundary | WNS −10.860 → −10.502 ns |
| Cache flush scan → data/counters/write data | register the flush-scan owner/index before the data-array read | 35 412 → 108 failing endpoints (WNS −1.190 ns) |
| NPU descriptor error check → engine start | pipeline CHECK/VERIFY into their own states | WNS −1.190 → −0.688 ns |
| Placement and routing | `place_design -directive Explore`, `route_design -directive Explore`, `phys_opt_design -directive AggressiveExplore` | WNS −0.688 → **+0.191 ns**, 0 failing |

The perf-event and NPU changes are measurement-only and self-contained; the
cache flush-scan registration is the highest-risk change and keeps the
coherence, warm-stop and reservation behaviour identical.

## Result

The all-engine coherent overlay closes at a 20 ns constraint with **WNS
+0.191 ns, TNS 0.000 and 0 failing endpoints** (56 320 timing endpoints), hold
met (WHS +0.031 ns), **48.17% LUTs, 22.86% BRAM, 24 DSPs**, zero routing errors
and reset signoff PASS.

## Physical acceptance

Two warm boots on the Pynq-Z1 at **50 MHz** running `reduce_parallel`: checksum
`0x5c808000` matches the independent oracle on both boots (232 958 cycles,
`clock_hz=50000000`), with a clean STOPPED snapshot.

## Explicit non-goals

No new features, no shared-L2 changes, no change to any frozen v1.0 address,
register or ABI, and no change to the L1 coherence protocol's observable
behaviour. The only intended difference is timing (and the per-tile cycle count
and one-cycle perf-event latency that pipelining implies).
