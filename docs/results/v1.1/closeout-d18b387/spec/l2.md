# Phase 12.7 / v1.1: Shared L2 cache

Status: **in progress**.
Baseline: frozen Aster v1.0 at tag `v1.0` (`b050a81`).

This phase adds the one v1.0 freeze-point item deliberately deferred: a shared
L2 cache. It is a v1.1 change on a new line; the v1.0 tag and its interfaces
remain frozen. The L2 is a new subsystem and follows the project discipline:
contract, unit scoreboard, integration, coherence/regression, study, FPGA,
physical, closeout.

## Why a memory-side L2

The v1.0 memory hierarchy is two private write-back/write-allocate L1 D$ banks
with centralized MSI snooping (`aster_coherent_cache`) over shared RAM. The L1
module is the **point of coherence**: it holds both banks, so every peer
intervention is resolved internally and the backing port only sees refills,
writebacks, uncached/device traffic and flushes.

A shared L2 is therefore placed **between the L1 module's backing port and the
memory system**, caching the RAM range. Because every L1 refill, writeback,
flush and DMA device access crosses that port, the L2 stays coherent with the
L1s as long as it processes every backing write. The L1 coherence protocol is
unchanged, which keeps this a bounded addition rather than a coherence rewrite.

## Register contract

The L2 is **transparent**: it adds no MMIO page and changes no v1.0 address,
register or ABI. It is observed through the existing performance counters:
the L1→memory `backing_transactions` counter drops when the L2 absorbs traffic,
and the L2 exposes `access`, `miss`, `refill` and `writeback` event outputs.

## Behaviour

- Caches only `0x1000_0000–0x1001_0000` (RAM). ROM, MMIO and every other
  address bypass unchanged.
- **Read-allocate.** A read hit returns the line immediately; a read miss
  refills `LINE_WORDS` words from memory, installs the line, then serves.
- **Write-through, update, no write-allocate.** A write updates the line if
  present and writes memory. A write miss writes memory without allocating.
  This keeps RAM authoritative, so the L2 is trivially coherent with the
  write-back L1s and with DMA device writes.
- Replacement is round-robin within a set (direct-mapped when `LINE_COUNT == 1`).
- `ENABLE_L2=0` makes the L2 a pure pass-through, preserving the v1.0 baseline.
- Reset invalidates all lines; the L2 holds no dirty state, so a warm stop
  needs no flush.

## Coherence argument

Every path that could make an L1 copy and the L2 copy disagree crosses the L2:

| Path | L2 action |
| --- | --- |
| L1 refill (read miss) | read-allocate and serve |
| L1 writeback (M eviction) | update line if present, write RAM |
| L1 flush writeback | update line if present, write RAM |
| DMA device read (uncached) | read-allocate and serve |
| DMA device write (uncached) | update line if present, write RAM |
| ROM/MMIO | bypass |

Because RAM is always updated on every write, and the L1 module resolves all
peer interventions internally, no L1 can hold a value that the L2 does not also
have after the write completes.

## Verification and acceptance gates

- [ ] Contract frozen.
- [ ] Unit scoreboard: read hit/miss/refill, write-through update and
      no-allocate, bypass for non-RAM, replacement, reset.
- [ ] Coherent-top integration with the L2 disabled reproducing the v1.0
      baseline exactly.
- [ ] Coherence regression: the full `make check` and every workload checksum
      pass with the L2 enabled.
- [ ] L2 size/enable sweep with an independent oracle, answering "how much do
      L1/L2 cache sizes affect real workloads".
- [ ] Frozen v1.0 interface guard still green (no address/ABI change).
- [ ] Routed all-engine overlay with reset/timing/HWH signoff.
- [ ] Physical Pynq-Z1 capture with two warm boots and a stopped-state snapshot.
- [ ] Self-contained closeout bundle and read-only audit.

## Explicit non-goals

This phase does not add a directory protocol, a write-back or inclusive L2,
L1/L2 inclusion policy, L3, prefetching, or any change to the frozen v1.0
addresses, registers, ABIs or the L1 coherence protocol. Interrupt priority and
RTL frequency optimization remain out of scope.
