# v1.3: Close the slow corner at 100 MHz

Status: **in progress**.
Baseline: Aster v1.2 at `4955bfb`.

v1.3 pipelines the frozen design so its **slow-corner static timing closes at
100 MHz** (10 ns). The silicon already runs the full heterogeneous pipeline
correctly at 100 MHz at room temperature; this phase makes that an operating
point the toolchain will actually sign off, rather than a bench observation.

## Measured starting point

| Metric | Value |
| --- | --- |
| Functional ceiling (Pynq-Z1, room temperature) | 100 MHz, identical oracle checksum |
| Slow-corner closure at the 32 ns constraint | 34.9 MHz (WNS +3.384 ns) |
| Slow-corner closure at the 10 ns constraint | ~47.8 MHz (WNS −10.860 ns, 38 680 / 55 599 endpoints fail) |
| Worst path at 10 ns | 20.9 ns, NPU `rows` → engine `state` |

See [`docs/results/frequency/`](../results/frequency/README.md).

## Critical path clusters to pipeline

| Cluster | Delay | Route | Levels | Risk |
| --- | ---: | ---: | ---: | --- |
| Perf-counter events → counters | ~20 ns | high | 22–34 | low (measurement-only) |
| NPU descriptor/tile address → state/values/address/error | ~20.5 ns | 42% | 27–28 | moderate (self-contained) |
| Cache `flush_position` → data/counters/write data | ~19.6 ns | 70–81% | 22–34 | high (coherence + warm-stop) |

## Plan

1. **Perf events.** Register the event/increment inputs at each performance
   block boundary. The counters are measurement-only, so a one-cycle event
   latency changes no functional behaviour, register map or ABI; only the
   retained counter values shift by a cycle.
2. **NPU engine.** Register the captured descriptor and the tile/row/column
   counters before the address arithmetic, splitting the ~28-level cone. The
   engine keeps its start/done handshake; the per-tile cycle count changes.
3. **Cache flush scan.** Register or replicate the flush-scan address so the
   data, counter and write-data cones are driven locally. This touches the
   coherence and warm-stop lifecycle and is the highest-risk change.
4. Re-close at a 10 ns constraint, iterate on the remaining critical paths, and
   record the achieved WNS.
5. Re-run `make check`, the workload oracle suite and the coherence/litmus
   tests; rebuild the overlay; re-capture physically at the new frequency.

## Verification and acceptance gates

- [ ] Contract frozen.
- [ ] Every pipelined block passes its unit scoreboard and the workload oracle.
- [ ] `make check` passes with the pipelined RTL.
- [ ] The coherence, warm-stop and reservation tests pass unchanged.
- [ ] Routed overlay closes at the target period with a positive WNS.
- [ ] Physical capture at the achieved frequency with the oracle checksum.
- [ ] Frozen v1.0 interface guard still green.
- [ ] Self-contained closeout bundle and read-only audit.

## Explicit non-goals

No new features, no shared-L2 changes, no change to any frozen v1.0 address,
register or ABI, and no change to the L1 coherence protocol's observable
behaviour. The only intended difference is timing (and the per-tile cycle count
and one-cycle perf-event latency that pipelining implies).
